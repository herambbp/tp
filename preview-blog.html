My Journey with React Hooks: From Confusion to Clarity

How I learned to stop worrying about class components and embrace the functional future of React.

When React Hooks were first announced at React Conf 2018, I was skeptical. After years of writing class components with lifecycle methods I knew by heart, the idea of managing state and side effects with simple functions seemed almost too good to be true. But as I dove deeper into this new paradigm, I discovered a more elegant way to write React applications.

The learning curve wasn't exactly smooth. I made every mistake in the book: forgetting dependency arrays, creating infinite loops, and wrestling with stale closures. But each mistake taught me something valuable about how React works under the hood.

The Breakthrough Moment

My understanding of hooks crystallized when I stopped trying to map them directly to class component lifecycle methods. Hooks aren't just a different syntax for the same concepts—they represent a fundamentally different mental model for building components.

"With Hooks, you don't think in terms of mounting and updating. You think in terms of synchronizing with external systems."

This shift in perspective changed everything. Instead of asking "which lifecycle method do I use?", I started asking "what does this component need to synchronize with?" The answer to that question naturally leads you to the right hook.

useState: More Than Just State

Let's start with the most fundamental hook. At first glance, useState seems simple: it gives you a value and a way to update it. But the real power comes from understanding that each call to useState is independent and can manage its own piece of state: 

const [count, setCount] = useState(0);
const [name, setName] = useState('');
const [isVisible, setIsVisible] = useState(true);

// Each piece of state is independent
// Updates are batched for performance
// Re-renders happen efficiently

Unlike class components where all state lives in a single object, hooks let you split state into logical pieces. This makes your code more modular and easier to refactor.

The best code is not the cleverest code—it's the code that's easiest to understand six months from now.

useEffect: The Swiss Army Knife

If useState is the heart of hooks, useEffect is the nervous system. It handles all the side effects your component needs: data fetching, subscriptions, manual DOM manipulation, and more.

The key insight is that useEffect runs after every render by default, but you can control when it runs with the dependency array. This is where many developers (including past me) get tripped up.

Three Rules That Changed My Understanding

After countless hours of debugging, I distilled my learnings into three rules:

  • Always declare dependencies honestly – Don't lie to React about what your effect needs
  • Think in synchronization – Your effect should sync with external state, not cause it
  • Cleanup is crucial – Always cleanup subscriptions, timers, and event listeners

These rules might seem obvious now, but they represent hundreds of hours of debugging and reading documentation. If you internalize them early, you'll save yourself countless headaches.

Custom Hooks: Where It All Clicks

The moment hooks truly clicked for me was when I wrote my first custom hook. Suddenly, I could extract complex logic into reusable functions that felt natural to use. No more render props, no more HOCs—just composition through simple functions. 

function useWindowSize() {
  const [size, setSize] = useState({
    width: window.innerWidth,
    height: window.innerHeight
  });

  useEffect(() => {
    const handleResize = () => {
      setSize({
        width: window.innerWidth,
        height: window.innerHeight
      });
    };

    window.addEventListener('resize', handleResize);
    return () => window.removeEventListener('resize', handleResize);
  }, []);

  return size;
}

This pattern of encapsulating logic in custom hooks has made my code dramatically more reusable and testable. Each hook does one thing well, and they compose beautifully.

Lessons Learned

Looking back on this journey, I realize that learning hooks wasn't just about learning a new API. It was about learning to think differently about how components work. Here are the key lessons that stuck with me:

  • Embrace the functional paradigm—don't fight it
  • Read the official docs thoroughly (they're excellent)
  • Use the ESLint plugin for hooks—it catches so many mistakes
  • Start with simple hooks and gradually build complexity
  • Don't be afraid to write custom hooks

Today, I can't imagine going back to class components. Hooks have made my code more readable, more reusable, and frankly, more fun to write. The initial confusion was worth pushing through.

If you're just starting your hooks journey, be patient with yourself. Every expert was once a beginner who refused to give up. The confusion you feel now will transform into clarity with practice and persistence.
